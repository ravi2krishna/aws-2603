    -> Data center

        -> A data center is a physical facility or building that houses 
        groups of networked computer servers, data storage drives, and network equipment 
        used by companies to store, process, and share digital information and run applications.

        -> https://datacenters.microsoft.com/wp-content/uploads/2025/11/OMB-Datacenter-11_11-Hero.jpg

        -> Main Parts of a Data Center:
        
            -> Servers: 
                
                -> High-power computers that process data and run software programs.
                
            -> Storage Systems: 
            
                -> Hard drives and arrays that hold large amounts of digital files and records.
                
            -> Network Gear: 
            
                -> Routers, switches, and firewalls that move data safely in and out of the facility.
                
            -> Cooling and Power: 
            
                -> Heavy-duty air conditioners, fans, backup generators, and power grids to 
                keep machines running non-stop.

        -> IAAS - Infrastructure As A Service 

            -> IAAS Model Provides Raw Computing Infrastructure Like Servers, Storage, Network

            -> You Manage Underlying Components On Top Of Infrastructure 

            -> https://miro.medium.com/v2/resize:fit:1400/1*VIzchB0D3t1awTzj3sfe1g.png

            -> Server For Myntra Application

                -> Hardware and Virtualization will be provided and managed by Vendor 

                    -> 4 CPU's - 16 GB RAM - 500 GB SSD Storage - Networking 

                -> As Customer (You) Need To Manage 

                    -> Setup Linux Ubuntu Operating System

                    -> Setup Tomcat / Jboss / Web Logic  

                    -> Setup Runtime (Java, Python etc)

                    -> Setup Data (Code, Database)

                    -> Setup Myntra Application Running 

                -> Examples: AWS EC2 - AWS VPC - etc 

                -> Cost: ₹₹₹₹ 

                -> Human Resources: More (Different Admin, Developers)


        
        -> PAAS - Platform As A Service 

            -> PAAS Model Delivers Frameworks For "Developers" 
            to Build, Test and Deploy Softwares / Applications 
            Without Managing Underlying Hardware, Middleware and Runtime.

            -> Server For Myntra Application With Linux Ubuntu Operating System, 
            Tomcat Server and Java Runtime.

            -> Hardware, Virtualization and Platform For You Applications 
            will also be provided and managed by Vendor 

                -> 4 CPU's - 16 GB RAM - 500 GB SSD Storage - Networking - Linux Ubuntu OS -> Tomcat Installed and Running -> Java Installed 
                    
            -> As Customer (You) Need To Manage 

                -> Data and Applications Only 

            -> Examples: AWS Elastic Beanstalk - AWS RDS - AWS EKS etc 

            -> Human Resources: Less (Developers)
            
            -> Cost: ₹₹₹₹₹₹₹₹₹

        
            -> NOTE: We may use standalone Service i.e Only IAAS or Combine IAAS + PAAS 

            -> Myntra Application Requires (Developers Perspective)

                -> Web Server it's easy to manage - IAAS 

                -> Database Server it's bit difficult to manage - so i will choose PAAS 

                -> Solution 1 : Web Server (IAAS) + Database Server (IAAS) - ₹₹

                -> Solution 2 : Web Server (IAAS) + Database Server (PAAS) - ₹₹₹₹ 

                -> Solution 3 : Web Server (PAAS) + Database Server (PAAS) - ₹₹₹₹₹₹₹₹₹₹ 

        
        
        -> SAAS - Software As A Service 

            -> SAAS Model Provides Fully Functional and Ready To Use Softwares / Applications 

            -> Generally Accessed Via Web Browsers 

            -> Examples: Salesforce - Microsoft 365 - Google Workspace 

            -> Server For Myntra Application With Linux Ubuntu Operating System, 
            Tomcat Server, Java Runtime, Design Database and Code Myntra Application. 

            -> Hardware, Virtualization, Platform and Application also provided and managed by Vendor 

                -> 4 CPU's - 16 GB RAM - 500 GB SSD Storage - Networking - Linux Ubuntu OS -> Tomcat Installed and Running -> Java Installed -> Data and Applications is also ready to use 
                    
            -> As Customer (You) Need To Manage 

                -> NOTHING 

            -> Examples From AWS: AWS Chime(Online Meetings, Video Conferences) - AWS Workspaces etc 


            -> Customer-1: Needs Only Hardware i.e Only IaaS

            -> Customer-2: Needs Hardware + Platform i.e IaaS + PaaS 

            -> Customer-3: Needs Direct Application i.e SaaS 


        -> IaaS: Rent Infrastructure - You Manage OS, Middleware & Apps - AWS EC2, AWS VPC, AWS EBS

        -> PaaS: Build & Deploy Apps - You Manage Apps - AWS Elastic Beanstalk - AWS RDS, AWS EKS 

        -> SaaS: Use Apps - vendor manages everything - AWS Chime - AWS Connect - AWS Workspaces

    -> AWS Global Infrastructure 

        -> AWS global infrastructure is the most secure, reliable, and extensive cloud, 
        providing diverse infrastructure solutions for running your applications.

        -> https://aws.amazon.com/about-aws/global-infrastructure/

        -> The AWS Cloud spans "124 Availability Zones" within "39 Geographic Regions", 
        with announced plans for 7 more Availability Zones and 2 more AWS Regions 
        in the Kingdom of Saudi Arabia, and Chile.

        -> In Terms Of AWS, Infrastructure Is Made Of 

            -> Regions 

            -> Availability Zones 

        -> AWS Provides It's Infrastructure For Customers Using Regions & Availability Zones 
        i.e Servers, Storage, Network, Database etc are present in Regions & Availability Zones 


        
        -> Regions 

            -> In AWS Region is a Geographic Location 

            -> Each region contains multiple isolated Availability Zones

            -> Regions operate completely independently from 
            one another to prevent cascading failures.

            -> Choosing a region close to your users minimizes network delay.

                -> https://cdn.britannica.com/96/212396-050-1FC95D3E/world-map-with-country-borders.jpg

            -> Compliance: Keep data inside specific geographic borders to meet legal rules.

            -> Cost: Prices for services can change depending on the region.

            -> New features or specific instance types may launch in certain regions first.


        -> Availability Zones (AZ)

            -> An AWS Availability Zone (AZ) is one or more discrete data centers with 
            redundant power, cooling, and networking within an AWS Region.

            -> Every region has at least three physically separate and isolated 
            data center groups to ensure high availability.

            -> Each AZ is physically separated by a meaningful distance (up to 100 km) 
            to prevent localized disasters from affecting multiple zones, 
            yet they are interconnected via high-bandwidth, low-latency private 
            fiber-optic networks.

            -> https://www.researchgate.net/profile/Ivan_Beres/publication/360541079/figure/fig1/AS:1154856056291328@1652350548135/AWS-Regions-and-Availability-Zones-Scott-nd.ppm

    -> Edge Locations

        -> To Understand Edge Locations, We Need To KNow About CDN - Content Delivery Network.

        -> CDN - A Content Delivery Network (CDN) is a geographically distributed 
        group of servers that speeds up internet content delivery by 
        caching assets closer to users. 
        By reducing the physical distance data must travel, CDNs minimize latency.

            -> https://www.muvi.com/wp-content/uploads/2017/07/CDN_Muvi.png

        
        -> An AWS Edge Location is a data center in the AWS global network
        to store cached content (images, videos, pdf etc) and 
        process requests closer to end-users, drastically reducing latency by 
        serving data from the nearest point rather than a distant location.
    
    
    
    -> AWS VPC (Virtual Private Cloud)

        -> A Virtual Private Cloud (VPC) is a logically isolated, 
        private network environment within a public cloud.

        -> https://www.akamai.com/site/en/images/article/2023/akamai-public-private-cloud.png

        -> https://images.netcomlearning.com/cms/images/virtual-private-cloud.jpg

        -> NOTE: Having VPC is similar to having your own data center inside AWS. 

        -> VPC is a service that lets customers(IBM) provision a logically isolated 
        section of the AWS Cloud where you can launch AWS resources(Servers) 
        in a VIRTUAL NETWORK that you define.

    -> VPC Components 

        -> Subnets
        
            -> Segments of a VPC's IP address range that group resources based on 
            security and connectivity needs (e.g., public subnets for websites, 
            private subnets for databases).

            -> A subnet or sub network is an logical subdivision of an Amazon Virtual Private Cloud (VPC)

            -> Most Popular Applications
        
                -> https://en.wikipedia.org/wiki/Programming_languages_used_in_most_popular_websites


        -> Route Tables 

            -> Rules that dictate where network traffic is directed.

            -> A route table contains a set of rules called routes, 
            that are used to determine where network traffic is directed.

        
        -> Gateways 

            -> Connection points that bridge your VPC to the external internet

            -> Internet Gateway

                -> An Internet Gateway must be attached to a VPC if the resources inside the VPC 
                need to connect to resources via the open internet.


        -> Network Access Control List (NACL)

            -> Virtual firewalls that control inbound and outbound traffic at the subnet level.


        -> Security Groups (SG)

            -> Virtual firewalls that control inbound and outbound traffic at the instance level.
